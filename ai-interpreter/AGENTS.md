# AI interpreter: ports and adapters

Do not edit this file, `CLAUDE.md`, or `.cursor/rules/*.mdc` unless the user explicitly asks to change the rules. `tests/test_pipeline_gates.py` fails the build when the rules or the CI gates are removed.

The screening flow (API, pipeline, rules, database) asks an interpreter for VIA JSON. It does not know where the model runs.

## The port

`ViaInterpreter` in `app/services/interpreter.py`:

- `interpret(image_bytes, context, examples, before_bytes) -> dict`
- `engine`, `model`, `uses_references`

`build_interpreter(config)` is the only place that chooses an adapter.

## Adapters

| Runtime | Adapter | How it is selected |
|---|---|---|
| Weights on this machine | `LocalVisionInterpreter` | `INTERPRETER_MODE=local`, or `auto` when `models/base` exists |
| Any GPU host | `RemoteInterpreter` | `INTERPRETER_MODE=remote` plus `REMOTE_MODEL_URL` |
| No model | `HeuristicInterpreter` | `INTERPRETER_MODE=heuristic`, or `auto` with no weights |

`scripts/model_server.py` is the process a GPU host runs. Colab, Kaggle, and a VM are different ways to start that process. They are not new modes.

## Adding a runtime

1. Add a class next to the other adapters. Set `engine`, `uses_references`, and `interpret`.
2. Return it from `build_interpreter`.
3. Leave `app/api.py`, `app/services/pipeline.py`, and `app/services/rules.py` unchanged.

Another URL is not a new class. Set `REMOTE_MODEL_URL`.

## Do not

- Import `torch`, `transformers`, `peft`, `huggingface_hub`, `openai`, or `kaggle` outside `interpreter.py`, `scripts/model_server.py`, `scripts/pull_model.py`, and `scripts/finetune_via.py`.
- Branch the pipeline or the API on Colab, Kaggle, CUDA, or a vendor name.
- Name a new `INTERPRETER_MODE` after a vendor.

`tests/test_ports.py` fails the build when this boundary is crossed.

## Pipeline the training work goes through

GitHub Actions (`.github/workflows/ci.yml`) is the gate. A Kaggle training push happens only after these jobs are green:

1. Secret scan (`kaggle/scan_secrets.py` and gitleaks). A tracked token fails the build.
2. Type check (`mypy` on `app/services/interpreter.py`).
3. Unit and integration tests, including the ports check.
4. Code-injection tests. Patient ids, filenames, ages, and report notes are data.
5. Memory tests on the CPU heuristic path.
6. AI contract tests. CI checks the VIA JSON shape. A live model answer is produced on Kaggle after this passes.

The job `push training job to kaggle` then runs, on `main` only. It packages source with `kaggle/prepare_kernel.py` and pushes a kernel. It does not start when the secret `KAGGLE_API_TOKEN` is missing. The public kernel is `mwimulebienvenu/viscan-via-train` and the public dataset is `mwimulebienvenu/malhari-via`. A repository variable with the same name overrides either id. The images stay on Kaggle, and training stops when that dataset has no CIN folders.

Change training settings in `kaggle/viscan-train/train.py`. Leave the API, pipeline, and rules unaware of Kaggle.
